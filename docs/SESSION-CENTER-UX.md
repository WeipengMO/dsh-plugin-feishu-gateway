# 会话管理：归档、恢复与聊天关联

入口：**DSH Web → 飞书管理 → 会话与消息 → 会话管理**。

核心原则：**DSH 负责保存真正的对话历史，飞书插件负责聊天与原生 Session 的连接**。界面不应把技术 ID 当成默认识别方式。

## 四个入口

| 入口 | 用途 |
| --- | --- |
| **对话历史** | 查看私聊、群聊与定时任务的 DSH 历史，按名称/来源/状态查找 |
| **已归档** | 查看隐藏于常用侧栏的 DSH 会话；当前 DSH 支持恢复时可操作 |
| **飞书聊天关联** | 查看飞书聊天连接到的原生 DSH Session，可隐藏或解除关联 |
| **整理与清理** | 预览飞书工作区归属变更、调整自动归位；查看真实删除的开发边界 |

默认显示标题、类型、状态和可验证的活动时间。原生 ID、聊天引用、机器人 ID 等放进「查看技术信息」；手机端使用卡片布局。

## 操作说明

| 动作 | 影响 | 是否清除 DSH 历史？ |
| --- | --- | --- |
| **归档 DSH 会话** | 从常用工作区/侧栏隐藏，保留原始记录 | **否** |
| **恢复归档** | 重新显示之前归档的原生 Session（需要 DSH 提供 `unarchiveSession`） | **否** |
| **隐藏飞书关联** | 标记该飞书聊天关联为隐藏，后续成功对话可能重新活动 | **否** |
| **解除飞书关联** | 移除飞书聊天与旧 Session 连接；下条消息创建新 Session | **否** |
| **回收站 / 永久删除** | 计划支持恢复期限、过期清理与实测磁盘回收 | **尚未实现** |

“未关联”只说明没有匹配的当前飞书绑定，**不代表会话无用或允许删除**。原生归档仅用于当前没有飞书绑定、未运行、未被活动定时任务引用的旧会话。绑定操作由 Gateway 独占进程在实际执行前再次检查状态。

## 重要区别：创建时间不是最后使用时间

某些原生旧 Session 只提供 Header 创建时间，不能推断最后一次对话发生在何时。新版界面会显示「最近活动未记录」，并独立给出创建时间。自动清理的未来设计**不能把创建时间代替最后使用时间**；Gateway 状态过期也不能假装“空闲”。

## 什么是安全的删除流程？

真正删除需要两条独立能力：

1. **归档**：日常整理，不删数据，可恢复。
2. **回收站**：用户明确移入，设定保留期限（建议 30 天），期间可恢复。
3. **永久删除**：确认后真正删除 DSH 原生历史、索引和关联，核实释放空间。

建议未来支持 **90 天未使用自动归档**，并默认**关闭自动永久删除**。该策略只是待开发方案，当前没有定时物理清理任务或真实删除按钮。相关设计见 [Issue #37](https://github.com/WeipengMO/dsh-plugin-feishu-gateway/issues/37)。

## 技术边界与验收

当前管理 API 的原生归档要求二次预览及一次性令牌；恢复调用 DSH 可选 `WorkspaceRegistry.unarchiveSession`，不支持时禁用，不直接编辑 DSH 文件。飞书绑定的单条及最多 20 条批量操作有 Gateway owner 校验；“请求入队”不代表成功，应到告警中心看结果。

需要在真实 DSH 环境确认归档→恢复保持相同 Session ID、标题与历史；验证运行中、绑定中及定时任务引用的历史不能被误归档。更多技术细节见 [Session 生命周期](SESSION-LIFECYCLE.md) 和 [工作区整理](FEISHU-SESSION-ORGANIZATION.md)。
