# 会话管理：用户界面与数据边界

## 从用户角度理解四个入口

在「飞书管理 → 会话与消息 → 会话管理」中：

| 入口 | 显示什么 | 能做什么 |
| --- | --- | --- |
| **对话历史** | DSH 保存的飞书私聊、群聊和定时任务对话 | 搜索、筛选；对不再被飞书关联的旧对话进行**归档** |
| **已归档** | 从 DSH 侧栏隐藏、但仍保存数据的对话 | 查看并在 DSH 支持的版本中**恢复** |
| **飞书聊天关联** | 飞书聊天 → DSH Session 的当前映射 | **隐藏关联**、**解除关联**（绝不删正文），支持最多 20 条批量操作 |
| **整理与清理** | DSH 工作区自动整理、生命周期说明 | 预览或执行安全工作区整理；尚不执行真实删除 |

列表默认只展示对话标题、类型、最近使用和状态；会话 ID、Bot ID、聊天引用隐藏在「查看技术信息」和「更多筛选条件」。手机宽度下采用卡片式表格布局，不再必须横向滚动 700px 表格。

## 四种操作：不应混淆

### 归档

- 只是将 DSH 会话从常用侧栏隐藏；**原始历史、Token 记录、文件等不会因此删除**。
- 原生恢复入口调用 DSH WorkspaceRegistry.unarchiveSession（如果此 DSH 版本提供）。
- 不支持该接口时，恢复按钮禁用并说明原因；绝不直接编辑 workspace.json。
- 为避免误隐藏仍在被飞书继续使用的上下文，原生归档只允许未关联、未运行的历史。
- 当前已归档的记录不等于可删除，也不等于回收站。

### 隐藏或解除飞书关联

- 「隐藏关联」只标记 Gateway 的绑定记录，不改变 DSH 侧栏/日志；新消息成功执行时可以重新活动。
- 「解除关联」移除飞书聊天 → DSH Session 映射；下一条飞书消息将创建新的 DSH Session。
- 这两者都**不删除原生对话**，也**不承诺释放磁盘空间**。
- 操作仍保留 Gateway owner 进程审查、一次性确认票据、活动任务/审批/Outbox 检查和逐条执行结果。

### 回收站与永久删除（未实现）

按 [Issue #37](https://github.com/WeipengMO/dsh-plugin-feishu-gateway/issues/37) 实现。不要把归档简单改名为回收站，也不要把解除绑定包装为删除。用户希望的是以下闭环：

```
正在使用 ──归档──> 已归档 ──恢复──> 正在使用
    │                  │
    └──移入回收站──────┴──> 回收站 ──恢复──> 原有状态
                                 │
                                 └──明确确认/到期──> 永久删除
```

永久删除必须通过经验证的后端实现，真正移除 DSH 事件日志、索引、工作区登记及外部引用，并实测释放的字节数。当前 DSH SessionPersistence 没有通用 deletion/retention seam，不能靠后台推测路径后直接删文件。**本分支不会提供假删除按钮。**

## 自动历史整理建议

- 建议从 **90 天未使用自动归档** 开始，排除活跃任务、绑定/定时任务目标、已收藏和被其他工作区使用的会话。
- 回收站恢复期建议 **30 天**，可选 7、30、90 天。
- **自动永久删除默认关闭**；首次启用必须 dry-run 显示候选标题、原因、实际存储量和跳过原因，再由用户确认。
- 以最后活动时间判断，不是创建时间。
- 需要每次单一 Gateway owner 判定、DSH 写锁与活动状态、任务绑定和未发送消息校验，不能使用仅在 Web 端缓存的过期状态。
- 每一步结果必须可查；清理空间统计不能拿关联 JSON 字节数冒充原生历史大小。

## 技术和兼容性

- Web Admin 新增 `POST /api/feishu-admin/sessions/native/restore`，请求体 `{ "sessionRef": "<16 hex>" }`。
- 服务端校验授权、会话列表中唯一的真实归档引用、DSH 原生恢复能力，并经过单 Web owner 串行化执行。
- 返回 `restored: true, nativeHistoryPreserved: true`；不能恢复时返回 501，不会假成功。
- 原生 Session 归档仍使用现有预览和 30 秒一次性令牌；恢复不删除日志、不建立飞书绑定。
- 这次 UI 重构不改变 Gateway 接收、路由、重试或运行中 Session 的执行行为。

## 验收

1. 进入会话管理时，默认显示「对话历史」，不再堆叠两套有重复指标的后台页面。
2. 私聊/群聊/定时任务标题与类型可识别，搜名称、按日期筛选均正常。
3. 未关联旧对话 → 归档 → 已归档；可用运行时 → 恢复；旧运行时按钮禁用。
4. 飞书关联的归档与解除操作仍通过 owner 确认与审计；DSH 历史不被删除。
5. 正在执行、仍被飞书绑定或被定时任务使用的会话不能被原生归档。
6. 375px 手机页面列表为垂直卡片，可见操作结果，不出现大范围横向滚动。
7. 代码测试、真实 DSH Web + Gateway 双 Profile 回归，验证不触碰用户现有会话与消息正文。
