# Web Admin 视觉与交互规范

适用范围：`web-admin/src` 下的飞书管理后台，包含总览、会话管理、任务与消息、定时任务、接入与权限、Agent 档案、Skills、用量与审计、运维与诊断、模型与连接。

## 1. 产品目标

- 按用户任务组织界面，而不是按 Gateway 内部 DTO、数据库结构或技术名词组织。
- 首屏先回答“服务是否正常”“是否需要处理”，再呈现操作与技术细节。
- **一个语义区块只设置一层容器**。卡片里可以有表单字段、表格行，不应再多次嵌套同等权重的带框卡片。
- 空数据是真实状态；不制造假数字，也不将“暂无记录”解释为“服务失败”。
- Web Admin 是飞书 Gateway 的管理界面，不修改 DSH Core、不伪造工具审批、不代替原生 Session。

## 2. 视觉 Token

所有颜色复用 DSH 当前主题，适配亮色和暗色；不要写死整体背景色。现有 CSS token：

| 语义 | 实现 |
| --- | --- |
| 页面文本 | `var(--foreground)` |
| 次要文本 | `var(--muted-foreground)` |
| 卡片背景 | `var(--card)` |
| 表单/弹出层背景 | `var(--background)` 或 `var(--popover)` |
| 强调/选中态 | `var(--primary)` |
| 分割线/弱边框 | `--fgw-ui-stroke`，由宿主 `--border` 降低对比度 |
| 弱色区域 | `--fgw-ui-inset`，由宿主 `--muted` 派生 |
| 控件统一规格 | `--fgw-control-radius`(9px)、`--fgw-control-height`(38px)、`--fgw-control-font-size`(13px)、`--fgw-control-pad-x`(11px)，在 `.fga-root` / `.fgw-root` 上定义 |

间距采用 **8 / 12 / 16 / 24 px**，在根节点定义 `--fgw-ui-gap-1` 至 `--fgw-ui-gap-4`。控件、行间距应按这个节奏排列，不在相邻区块随意混用 5、13、19、27 px。

字重层级：页面标题优先 20–24 px、区块标题 13–15 px、主体 12–13 px、注释 11–12 px；仅关键指标数字放大。段落行高维持约 1.5–1.7，标签使用简短中文。

## 3. 布局层次

- **导航**：按「日常管理」「机器人与 Agent」「统计与诊断」分组，二级功能在对应页面内使用同一套浅色分段切换。避免重复的导航捷径。
- **总览**：服务状态、指标、可操作告警、当前任务/连接；不再放静态消息链路图和重复侧栏链接。
- **配置页**：标题与一行解释 → 控件/选项 → 适用时机说明 → 唯一的保存操作区。保存状态要区分“未保存”“已提交”“待重启生效”。
- **会话管理**：单独一级入口，包含对话历史、已归档和飞书聊天关联，不再藏在「任务与消息」二级页签下。搜索和批量操作直接相邻，进阶筛选折叠。
- **安全权限**：先选择文件访问级别、额外权限处理、额外目录；三个区块的标题、说明和控件按相同间距组织。只读状态放在可展开的详情区，不与编辑区域重复。
- **审批审计**：两个核心数字与轻量元数据；待审批、永久授权、近期审批是明确区块。没有记录时使用紧凑空状态，避免三层大虚线框。
- **用量图表**：桌面将日期范围与 Token 指标并排，窄内容区换行；指标、趋势与具体日期数据形成一条阅读路径；鼠标悬停和触摸均可读取精确值。

## 4. 组件行为

### 统一选择控件（下拉、筛选与分段按钮）

- 所有下拉都遵循同一套控件规格：原生 `<select>`、用量筛选、定时任务选择和可搜索选择器共用圆角、高度、字号、边框与焦点环；不允许各页面分别定义尺寸或半径。
- 下拉箭头由主题渐变绘制，不依赖操作系统原生箭头；候选列表背景与文字使用 `--popover` / `--foreground`，亮色与暗色主题均需可读。
- 可搜索选择器（`fga-search-picker`）与原生下拉是同一控件的两种表达方式，触发器尺寸和焦点态必须一致。
- 分段切换（如权限模式）是"按钮形式的选择控件"，复用同一高度与圆角；选中态用主题色，不用灰色禁用态代替说明。

### 模型选择器

- 主模型：**单个输入型下拉列表**，聚焦后展示候选，键入名称/提供方/模型 ID 即过滤。
- 备用模型：与主模型同源的搜索下拉，多选以可移除的标签展示，并清楚标明尝试优先级。
- 支持鼠标点击、方向键、回车确认、Escape 收起；候选滚动区域设置高度上限。保存前必须选定候选项，输入关键词不应自动更改路由。
- 候选列表仅使用 Gateway 当前报告或明确保存的模型，不凭空补全不可用提供方；保留原有副作用防重试限制。

### Agent 预设及刷新按钮

- 预设候选菜单采用主题化的组件而非原生操作系统下拉层；在亮色、暗色主题下均保持对比度一致。
- 「继承」沿用原 Profile 预设；「不指定」显式清除 Profile 预设、采用 DSH 默认组合。这两者不可仅因标签相似而合并。
- 旧 `workspace` 必须保持作为独立 Agent 工作目录的隔离校验边界；仅从主配置表单隐藏，不从服务端删除。
- 刷新操作统一为紧凑的图标加文字按钮；状态变更、保存和重启不能使用相同刷新图标。

### 数据图表

- 优先测量 **实际内容容器宽度**（`ResizeObserver`），不要只根据浏览器 `window.innerWidth` 决定紧凑布局。
- 有效数据点支持 `pointermove`、点击固定、方向键逐点查看，提供可读的值和日期；Escape 清除选择。无覆盖日期应标成“无历史记录”，不当作零。
- 使用者不能只靠颜色、纯 SVG `title` 或悬停获取重要数据；保留文字检视区。

### 编辑安全

- 已修改的表单、档案和技能导航离开或刷新前提示。
- 服务器拒绝保存时保留草稿；异步入队的任务必须区分“已提交”与“执行成功”。
- 高风险操作（永久删除、完全访问、重启通道、长期授权撤销）保留明确的确认和作用范围。

## 5. 响应式与可访问性

优先使用容器查询：**1000 / 650 / 410 px**，保证 DSH 侧栏收缩内容时布局仍正常。至少核对以下场景：

| 场景 | 验收要点 |
| --- | --- |
| 桌面 1440 / 1024 px | 双列信息完整、弹出菜单不被邻近卡片遮挡 |
| 平板约 768 px | 网格折叠、按钮可换行，表格在自身容器内滚动 |
| 手机约 390 px | 会话管理的三个分类保持一行、主要按钮可点，标题不重叠 |
| 125% / 150% 缩放 | 不发生页面横向溢出或固定宽卡片错位 |
| 亮色 / 暗色模式 | 对比度充足、焦点态清晰、选中态不用系统原生黑色菜单 |
| 鼠标 / 键盘 / 触控 | 模型候选与图表均能实际操作和读取内容 |

注意 `role`、`aria-label`、`aria-expanded`、`aria-live`、输入框焦点和 Escape 行为。禁用状态要给出原因，不能以灰色按钮代替说明。

## 6. 回归验证

在仓库根目录执行：

```bash
pnpm run typecheck
pnpm run build
pnpm run test
pnpm --dir web-admin test
pnpm run pack
```

CI 成功只能证明编译与自动化契约，不能证明真实 DSH Web 的所有页面像素和移动端交互。人工验收后方可考虑合并与发布。

任何后续新增 Admin 页面：先复用现有 `fgw`/`fga` 组件和主题 Token，再增添有实际语义的结构；不要为了“现代感”反复套卡片、阴影和分隔线。
