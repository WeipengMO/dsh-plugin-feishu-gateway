# 端到端验收（真实 DSH 与飞书）

自动化测试主要使用 Mock，不会自动连接真实飞书租户。这里列出真实部署回归需要验证什么，以及如何安全准备测试环境。

## 验收环境

- 使用**独立测试 Profile / stateDir**，不要覆盖生产正在使用的 Inbox、Outbox、Session 或凭据。
- DSH / Node 版本满足仓库 [Gateway](../package.json)、[Admin](../web-admin/package.json) 的依赖声明。
- 用飞书测试应用，完成真实长连接事件订阅、发送权限、可用范围和白名单设置。
- 需要真实模型测试时，使用测试环境认可的模型凭据；不要在命令、测试报告或日志里输出密钥。
- Gateway 应是**长驻 Host**，一次性启动即退出的 Session 不能证明跨消息上下文持久性。

## 分级运行

```bash
# 静态、构建、Mock、安全与文档链接
pnpm run verify
pnpm run test:coverage

# 原生 Agent 与 Session 桥接：不接真实飞书（Mock）
pnpm run e2e:mock

# 使用真实模型（需预先配置且隔离）
pnpm run e2e:real-llm

# 真实飞书预检与对话 Harness（需授权的测试应用）
pnpm run e2e:preflight
pnpm run e2e:feishu
```

脚本会按实际环境检查所需配置；未提供凭据或真实 Host 时应明确报告阻塞，不能标记通过。

## 最低真实验收清单

| 场景 | 期望 |
| --- | --- |
| 长连接 | Gateway 成功连接，重启后恢复连接 |
| 普通私聊 | 同一用户连续三轮消息复用上下文 |
| `/new` | 新消息进入新 Session，旧历史仍可查看 |
| `/cancel` | 当前聊天停止，不影响其他聊天，也不自动重放工具副作用 |
| 消息投递 | 飞书实际收到回复；Outbox 遇网络失败后安全恢复、不重复发送 |
| 工具审批 | 真正触发 `approval/request`，允许一次 / 拒绝 / 超时都正确处理 |
| CardKit | 流式进度、最终卡片、取消按钮和权限正确 |
| 群聊 | @ 与非 @、成员白名单、会话隔离和跨人审批安全 |
| 定时任务 | 创建、暂停/恢复、实际触发、通知回执与执行历史 |
| 会话管理 | 归档、恢复、解除关联；验证没有删除 DSH 原生历史 |
| 手机管理端 | 主导航、会话列表、筛选和操作按钮在窄屏可用 |

## 报告规范

每份验收要记录**提交 SHA、Gateway/Admin 版本、DSH 版本、运行环境、真实/Mock 类型、通过/失败项与可脱敏的证据**。部分流程要求管理员在飞书客户端手动操作或核对 OpenAPI，不能因为 CLI 返回 0 就声称对方已收到消息。

历史上单用户私聊的 rc.1 验收以及 rc.15 定时任务的 9/9 实机验收保存在 [历史资料](archive/README.md)，不是当前开发分支的自动验收结果。更多见 [开发与测试](DEVELOPMENT.md)。
