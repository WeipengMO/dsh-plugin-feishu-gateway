# 飞书会话工作区整理（技术参考）

本功能与**永久删除历史**无关。DSH 原生 Session 保存历史；WorkspaceRegistry 只负责侧栏显示和归属；Gateway 另有飞书聊天关联记录。普通用户应先阅读 [会话管理](SESSION-CENTER-UX.md)。

## 已实现的管理逻辑

- 原生 Session 的标题可以由 Gateway 使用可选的 DSH 标题服务生成（私聊、群聊、定时任务），用户手动修改的标题应保留。
- Web Admin 只读取 DSH 原生 Header，不调用 `ctx.agents.resume`，避免抢占正在执行会话的写锁。
- 「飞书会话」工作区自动归位**默认关闭**。开启后仅整理当前仍被飞书聊天关联或活动定时任务引用的 Session。
- 初次启用时，不会把所有历史、未知 Session 全部自动加入新工作区；旧目录的原生 `cwd` 不能强制改写。
- `/new` 解绑期间不能立即隐藏旧 Session，需等待新绑定实际出现；定时任务失联也设定可配置的宽限期。
- 手动取消归档后，已经处理过的历史不会被下一轮自动对账重复隐藏。

## 安全操作

1. 检查真实 Gateway 状态是否新鲜、DSH Header/Workspace 服务是否可用；离线时只允许只读浏览。
2. 打开「飞书管理 → 会话与消息 → 会话管理 → 整理与清理」。
3. 在高级设置中先**预览**待归位和待归档数量，确认与实际聊天/任务匹配。
4. 需要时启用自动整理，或手动执行整理。运行中、状态不明或原生活动检查失败的会话应跳过。
5. 去会话历史/已归档页面核对结果，不能因对账统计数字变化就认为历史已删除。

## 兼容性与验收

Workspace/Session API 在不同 DSH 版本可能不同；以当前部署的真实服务是否支持为准。需在隔离 Profile 中验证群聊、私聊、`/new`、定时任务重建、长任务、重启恢复和用户手动恢复后不重复归档。只读预览不会代替真实端到端验收。

旧版的架构和具体 API 文档可在 [技术架构](ARCHITECTURE.md) 阅读。真正的回收站和物理清理另见 [Issue #37](https://github.com/WeipengMO/dsh-plugin-feishu-gateway/issues/37)。
