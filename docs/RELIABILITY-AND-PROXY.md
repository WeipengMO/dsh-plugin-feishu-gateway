# Gateway 可靠性与错误恢复（技术参考）

用户日常配置见 [运维手册](OPERATIONS.md)，代理字段和启动链路见 [代理实现](PROXY-CONFIG-FLOW.md)。本文件说明不能被界面文案掩盖的执行边界。

## 消息生命周期

- **Inbox**：接收消息先持久化，再应答飞书；以 `message_id` 去重。重启恢复时只自动继续确认未开始的任务，不重放执行结果不确定的工具调用。
- **Outbox**：发送失败可以安全重试带有固定幂等键的出站消息；不能仅凭页面“已排队”声称投递成功。
- **DSH Session**：同一聊天复用原生 Agent/Session 上下文；超时或异常要保护历史数据，不能静默生成空 Session 覆盖旧绑定。
- **Operator mailbox**：管理命令由拥有 Gateway 状态目录的唯一进程处理，重新检查授权、任务、绑定版本及等待队列后执行。

## 超时、取消与审批

`/cancel` 或卡片取消只请求停止当前聊天运行中的任务；已发生的外部副作用无法撤销，不能因为一次取消就自动重试。原生审批需要 DSH 明确提出权限升级要求，卡片不能私自放行。服务重启、网络断开与模型失败时应保持安全默认，并提供可解释的告警和审计。

## 网络代理

网络代理由运行飞书通道的 Profile 读取，管理 UI 仅保存受控配置。代理连通性测试不能代替真实 Feishu WS、飞书 REST 和模型 API 的完整路径测试。代理启用、回退直连和清除操作均应在真实网络下验证。

## 运维边界

不要手动删除 `sessions.json`、`inbox.jsonl`、`outbox.json`、任意历史目录或 owner lock 来“修复”运行错误。先停止相关进程并备份，之后在已确认安全的维护窗口按 [排障手册](OPERATIONS.md) 处理。
