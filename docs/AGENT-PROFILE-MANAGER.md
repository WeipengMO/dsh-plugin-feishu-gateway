# 飞书 Agent 档案与记忆管理

入口：**DSH Web → 飞书管理 → Agent 档案**。这个页面管理的是 **飞书 Agent 的身份与指令文件**，而不是普通 DSH 工作区内任意文件；与普通 DSH 的档案保持隔离。

## 页面如何使用

1. 左侧选择文件，右侧使用 Markdown 编辑器编辑；支持行号、当前行高亮、语法着色、预览、版本历史和未保存变更提醒。
2. 可管理 `SOUL.md`、`IDENTITY.md`、`USER.md`、`TOOLS.md`、`MEMORY.md`、`AGENTS.md` 等飞书专用规则或记忆。
3. 使用文件的加载设置决定是否纳入后续 Agent 上下文；配置的上下文字节预算受后台校验。
4. 保存后在文件列表确认版本历史。需要恢复时先预览历史差异，再恢复到期望版本；不要误以为预览等于保存。
5. 若修改 Agent 的系统身份或提示规则，建议在飞书使用 `/new` 开始新 Session 检查效果；已开始的 Agent turn 不会被后台直接改写。

**保存成功不代表运行中的旧 Session 已重新加载新提示词**。修改规则之前先备份；不要把密钥、私人 token 或可执行凭据写入 Agent 文本。

## 为什么要独立工作区

Gateway 使用飞书专用 Agent cwd/指令覆盖层，避免「飞书身份」污染普通 DSH Web 对话。对于从旧版升级的部署，需要检查早期可能写在普通工作区 `AGENTS.local.md` 的飞书规则；迁移流程见 [档案隔离与旧配置清理](AGENT-PROFILE-ISOLATION.md)。

## 安全边界

- 管理端只允许受控范围内的文件路径和配置项，不接受任意路径穿越、symlink 或外部命令。
- App Secret 和模型 API key 不放在 Agent 档案中。
- 文件历史与备份在服务器侧保存；恢复需要用户明确操作，不自动覆盖其他 workspace 的文件。
- 对生产会话的验证应包括提示词加载、正常 DSH 会话隔离和重启后的持久化。

系统部署见 [首次部署](GETTING-STARTED.md)，管理端共用说明见 [Web 管理](WEB-ADMIN.md)。
