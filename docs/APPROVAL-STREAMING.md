# 飞书流式卡片与 DSH 原生工具审批

Gateway 可选使用飞书 CardKit 展示运行中的 Agent 状态与结果，并将 **DSH 自身产生的工具审批请求**送达授权的飞书聊天。卡片是交互入口，**不会覆盖 DSH 沙箱、工具权限和原生审批决策**。

## 两项独立设置

| 功能 | 效果 | 默认/安全边界 |
| --- | --- | --- |
| 流式回复卡片（`streamCards`） | 运行时显示生成进度，结束后在卡片显示最终回复 | 需显式配置；CardKit 更新失败可按现有 Outbox 退回文本 |
| 工具审批卡片（`approvalCards`） | 当 DSH 原生 `approval/request` 触发时展示允许一次/拒绝等操作 | 需显式配置；审批最终由 DSH 决定 |

是否需要人工审批取决于 DSH 实际沙箱与审批 preset（例如 `ask`），**不是开启 `approvalCards` 就会让每次 shell 工具调用都弹窗**。`allowed-once` 表示只授权这一次请求；超时、拒绝不应按“允许”继续执行。取消已开始任务不会回滚已有副作用。

## 在飞书开放平台准备

- 启用机器人及 `im.message.receive_v1`，配置发送机器人消息所需权限。
- 使用 CardKit 交互时启用对应卡片能力、`card.action.trigger` 事件及必要权限，创建并**发布**应用版本。
- 群聊的审批卡片还要满足群与成员隔离、按钮操作者身份校验；不能允许任意群成员点击其他人的审批。

详细权限见 [飞书应用配置](FEISHU-APP.md) 和 [群聊管理](GROUP-CHAT.md)。

## 管理与验收

1. 在 **飞书管理 → 模型与连接** 查看或修改流式卡片、审批卡片配置，并确认 Gateway 当前版本与 DSH 原生审批插件都已加载。
2. 保存后按页面提示在维护窗口重启 Gateway，使设置生效。
3. 用一个正常长任务验证进度更新、最终卡片和无重复回复；再模拟卡片发送失败，确认回退路径。
4. 用确实需要原生权限升级的工具调用触发审批，验证允许一次、拒绝和超时；检查未授权用户、重复点击、不同聊天的按钮不会越权。
5. 在 DSH Web 的审批审计及飞书消息中核对最终状态。

早期验收结果不能直接当作新版本或新群聊策略的实机验收。版本安装与升级统一见 [运维指南](OPERATIONS.md)。
