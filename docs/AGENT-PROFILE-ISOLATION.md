# 飞书 Agent 工作区隔离与旧规则迁移

当前 Gateway 可以为飞书 Agent 使用独立工作目录，避免飞书专用的身份和记忆规则出现在普通 DSH 会话中。旧版曾有将飞书托管指令写入普通工作区 `AGENTS.local.md` 的情况，因此升级后可能需要**一次人工清理**。

## 推荐结构

| 位置 | 职责 |
| --- | --- |
| DSH 普通工作区 | 普通 Web / 桌面会话、自有 `AGENTS.md` |
| 飞书 Agent 专用工作区 | 飞书身份、记忆、指令和工具说明 |
| Gateway 状态目录 | Inbox、Outbox、飞书聊天关联、运行快照及配置 |
| DSH 原生 Session 存储 | 原生聊天正文和上下文 |

这些是**不同数据所有权**。从 DSH Web 中归档一段飞书历史不会清除 Agent 档案，解除聊天关联也不会删除原生 Session。

## 旧部署迁移

1. 更新前备份两个 Profile 的配置、Gateway 状态目录和相关工作区指令文件。
2. 在普通 DSH 工作区检查 `AGENTS.md` / `AGENTS.local.md` 是否存在旧版飞书身份文本。**不要直接把整个文件删除**，它可能还包含用户自己的规则。
3. 在 **飞书管理 → Agent 档案** 检查飞书专用工作区是否已经存在且能加载正确规则。
4. 对可明确识别的旧托管规则，先预览 / 备份，再按管理端提供的清理确认操作移除；无法识别的内容应人工判断，不自动猜测。
5. 用一个新的飞书 `/new` 会话验证新工作区规则生效，同时验证普通 DSH 对话不再加载飞书身份。
6. 重启 Gateway/Web Admin 后复核。发现问题时从备份恢复，不要同时改动两套工作区并丢失基线。

## 注意事项

- 不自动迁移不明来源的旧 Session；旧 Session 的 `cwd` 可能已写入原生 Header，不能通过后台强制修改。
- 工作区隔离是提示规则和目录边界，**不是把 DSH Agent 数据复制进第二套 Agent 引擎**。
- 具体能否立即生效取决于 DSH 的原生上下文加载行为和新 Session 生命周期。
